# OpenZL compatibility matrix

How **openzl-express** relates to the OpenZL C library, frame format, and codecs.

## OpenZL library revision

This repo vendors OpenZL as a git submodule under `openzl/`.

| Field | Value |
|-------|--------|
| Submodule path | `openzl/` |
| Tracked commit (example) | `1c09ec4a5bc9de07c124affd3f8dfb2467c57698` |
| Library version macros | `ZL_LIBRARY_VERSION` **0.2.3** (`openzl/include/openzl/zl_version.h`) |
| Frame format | controlled by OpenZL `ZL_*_FORMAT_VERSION` — encode uses max supported |

**Rule:** frames produced by **native / CLI / this package** at a given submodule rev should decompress with any decoder built from the **same or newer** OpenZL that still supports that frame format version. Downgrading OpenZL may refuse older/newer frames.

Check your checkout:

```bash
git -C openzl rev-parse HEAD
grep ZL_LIBRARY_VERSION openzl/include/openzl/zl_version.h
```

## Wire contract (HTTP)

| Header | Values |
|--------|--------|
| `Accept-Encoding` (client) | `openzl` (explicit), `zstd`, `gzip`, `*` |
| `Content-Encoding` (server) | `openzl` \| `zstd` \| `gzip` \| (omit for identity) |
| `Vary` | always `Accept-Encoding` when middleware runs |

- **`openzl` is never selected via `*`** — clients must opt in.
- **`*` → gzip only** by default (not zstd, not openzl).
- zstd requires a Node build with zlib zstd (typically Node ≥ 22.15).

## Encode / decode backends

| Path | Encode | Decode |
|------|--------|--------|
| Native N-API (`prebuilds/`, `native/build/`) | serial + trained `.zlc` when supported | universal OpenZL frames |
| Worker pool → `zli` pipes | serial | universal |
| One-shot CLI | any profile / `-c` trained | universal |
| Browser WASM (`browser/dist`) | — (decode only) | universal (wasm64) |
| Node zlib | gzip / zstd | gzip / zstd |

### Interop expectation

1. **Native encode → CLI decode** and reverse should match for the same OpenZL rev.
2. **Node encode → WASM decode** should match for serial/trained frames built with standard graphs.
3. Goldens under `test/fixtures/goldens/` (generated by `scripts/test-trust.mjs`) are the regression corpus.

```bash
npm run build && node scripts/test-trust.mjs
```

## Profiles

Shipped profiles live in `profiles/` (`manifest.json` + `*.zlc`).

| Name | Type | Notes |
|------|------|--------|
| `serial` | builtin | Safe default (opaque bytes) |
| `timeseries`, `api-list`, `prose`, `binary`, … | trained `.zlc` | Built with `zli train` from sample corpora |

Trained frames embed the graph — decompressors do **not** need the `.zlc` file.

## Safety limits (decompress)

Defaults applied by `decompress(buf, options?)`:

| Option | Default | Purpose |
|--------|---------|---------|
| `maxInputBytes` | 64 MiB | Reject huge compressed payloads early |
| `maxOutputBytes` | 256 MiB | Reject zip-bomb style expansion after decode |
| `timeoutMs` | 30_000 | Wall-clock cap (native work may still finish in background) |

Violations throw `LimitError` with `code` ∈ `INPUT_TOO_LARGE` | `OUTPUT_TOO_LARGE` | `TIMEOUT`.

## Structured errors

| Class | Typical `code` |
|-------|----------------|
| `OpenZLCLINotFoundError` | `CLI_NOT_FOUND` |
| `CompressionError` | `COMPRESSION_FAILED` |
| `DecompressionError` | `DECOMPRESSION_FAILED`, `INVALID_FRAME` |
| `LimitError` | `INPUT_TOO_LARGE`, `OUTPUT_TOO_LARGE`, `TIMEOUT` |

All extend `OpenZLError`. Prefer `err.code` / `instanceof` over message parsing.

## Metrics

```ts
onCompress?: (m: {
  encoding: 'openzl' | 'zstd' | 'gzip' | 'identity';
  ratio: number;   // compressed/original * 100
  ms: number;
  bytesIn: number;
  bytesOut: number;
  profile?: string;
  fallbackFrom?: string;
}) => void;
```

Available on Express middleware, Fastify plugin, and `compressBody`.

## Upgrade checklist

1. Bump `openzl` submodule; rebuild CLI + native + WASM.
2. Re-run `npm run train:profiles` if compressor serialization changed.
3. Run `npm test` and `node scripts/test-trust.mjs`.
4. Re-generate goldens if frame format is intentionally broken (document in CHANGELOG).
5. Publish new prebuilds under a new git tag (`v*`).
